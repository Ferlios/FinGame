# Анализ данных FinGame

Эта папка — отдельный мини-проект по анализу данных. Он читает два источника:

- `MOCK_DATA (1).csv` из корня репозитория;
- синтетические данные прототипа из `financial-tamagotchi/data` и `financial-tamagotchi/reports`.

Скрипт проверяет качество данных, считает сводные таблицы, строит графики и собирает отчёт и дашборд.

> Все данные синтетические. Это учебный анализ, а не исследование реальных людей и не финансовый совет.

---

## Как запустить

Из корня репозитория:

```powershell
python -m pip install -r analysis/requirements.txt
python analysis/analyze.py
```

Нужны Python 3.10+ и пакеты `pandas`, `numpy`, `matplotlib`. Больше ничего не требуется: графики сохраняются в PNG, интерактивность не используется.

## Что получится

| Файл | Что это |
|---|---|
| `report.md` | Подробный отчёт на русском: методика, таблицы, графики, выводы и ограничения |
| `dashboard.html` | Автономный дашборд: один HTML-файл с встроенными картинками, открывается двойным кликом |

| `output/*.csv` | Очищенные данные и сводные таблицы |
| `output/summary.json` | Ключевые цифры в машинночитаемом виде |

## Что внутри отчёта

1. Объяснение «что такое анализ данных» простыми словами.
2. Инвентаризация данных и проверка качества.
3. Отдельный разбор `MOCK_DATA`.
4. Отдельный разбор трат игровых пользователей.
5. Игровая экономика: монеты, XP, здоровье, квесты.
6. Симуляция баланса: 400 игроков × 90 дней, перцентили и целевые коридоры.
7. Корреляции и — отдельно — почему они не доказывают причинность.
8. Общая сводка, ограничения и список того, каких данных не хватает.

---

## Почему два набора не объединяются

В `MOCK_DATA` есть только `id`, имя и флаг `Using finapp`. Там нет дат, сумм, категорий и общего с игрой `user_id`. Игровые пользователи — вымышленные персонажи `u_001…u_006` со своими архетипами. Любое объединение по имени было бы случайным совпадением, поэтому анализ идёт по каждому набору отдельно, а общая сводка собирает метрики, а не строки.

## Структура кода

`analyze.py` — один файл без скрытой магии:

- `load_data()` — чтение и нормализация;
- `quality_checks()` — пропуски, дубли, необязательные поля;
- `chart_*()` — по одной функции на график;
- `build_summaries()` — сводные таблицы и перцентили;
- `build_report()` — Markdown-отчёт;
- `build_dashboard()` — HTML-дашборд с base64-картинками;
- `main()` — сборка всего результата.

Чтобы изменить оформление или добавить график, достаточно править соответствующую функцию: остальные шаги не зависят от неё.
