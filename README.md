# FinGame · финансовый тамагочи

Учебный проект о том, как превратить контроль расходов в игру: питомец — это аватар бюджета, дневной лимит трат — его энергия, а записи о тратах двигают прогресс, дают монеты и опыт.

В репозитории лежат три вещи:

1. **Играбельный прототип** — один HTML-файл, открывается без сервера.
2. **Пакет синтетических данных** — пользователи, траты, состояния по дням, симуляция баланса.
3. **Анализ данных** — понятный отчёт с графиками, таблицами и оговорками.

> **Все данные синтетические.** В репозитории нет реальных людей, реальных трат или персональных данных. Это портфолио-кейс, а не финансовый продукт и не финансовый совет.

## Что умеет прототип

- запись траты с суммой, категорией и необязательной заметкой;
- энергия бюджета: чем больше трат, тем ниже энергия, а перерасход бьёт по здоровью;
- работа в мини-игре и заработок монет;
- три ежедневных квеста с наградами;
- XP, уровни, достижения и стрики;
- магазин: еда, косметика, темы комнаты, новые питомцы;
- итоги дня, недельный бонус и переход к следующему дню;
- сохранение прогресса в браузере.

Демо-состояние специально начато не с нуля: 7-й день, 4-й уровень, 640 монет и уже потраченные 570 ₽ — чтобы сразу было видно, как устроен интерфейс.

## Какие данные внутри

| Набор | Что описывает одна строка | Размер |
|---|---|---|
| `MOCK_DATA (1).csv` | пользователя демо-списка | 1 000 строк |
| `financial-tamagotchi/data/transactions.csv` | одну трату | 501 строка |
| `financial-tamagotchi/data/mock_users.json` | один игровой день | 180 строк (6 пользователей × 30 дней) |
| `financial-tamagotchi/reports/balance_runs.csv` | один прогон симуляции на 90 дней | 400 строк |
| `financial-tamagotchi/data/*.json` | контент игры | категории, квесты, магазин, уровни, достижения, питомцы |

Важно: `MOCK_DATA` и игровые данные **нельзя объединить**. В `MOCK_DATA` нет дат, сумм, категорий и общего `user_id` — только имя и флаг «пользуется FinApp». Игровые пользователи — вымышленные персонажи `u_001…u_006` со своими архетипами. Поэтому анализ идёт по каждому набору отдельно.

## Главное из анализа

- В `MOCK_DATA` 1 000 пользователей, из них 515 (51,5%) помечены как использующие FinApp. Это доля внутри файла, а не оценка рынка.
- В игровом наборе 501 трата на 283 260 ₽. Средний чек 565 ₽, медианный — 410 ₽: распределение смещено крупными покупками.
- Крупнейшие категории: продукты (70 750 ₽), покупки (46 720 ₽), транспорт (37 960 ₽), кафе (36 320 ₽).
- Из 170 активных дней 125 (73,5%) уложились в лимит, 45 — с перерасходом. Ещё 10 дней остались без записей.
- В симуляции медиана дохода — 117 монет в день, 11-й уровень к 30-му дню, 16-й — к 90-му. Ядро косметики закрывается примерно за 34 дня, полная коллекция — примерно за 128.
- Самые сложные квесты — «Экономный день» и «Дорога учтена»: в этой симуляции они не выполнены ни разу. Это повод пересмотреть условия, а не вина игрока.
- Корреляции (дисциплина ↔ монеты +0,73, дисциплина ↔ здоровье +0,83) — следствие заложенных формул, а не доказательство причинности.

Подробный разбор, графики и таблицы — в [`analysis/report.md`](analysis/report.md).

## Как воспроизвести

### Анализ данных

**Быстрый способ — ноутбук в Colab:** [открыть `FinGame_analysis.ipynb`](https://colab.research.google.com/github/Ferlios/FinGame/blob/main/analysis/FinGame_analysis.ipynb) и нажать **Runtime → Run all**.

Локальный запуск скрипта из корня репозитория:

```powershell
python -m pip install -r analysis/requirements.txt
python analysis/analyze.py
```

Скрипт пересоберёт графики, CSV, `report.md` и `dashboard.html`. Нужны только `pandas`, `numpy` и `matplotlib`.

### Данные и прототип

```powershell
cd financial-tamagotchi
python tools/generate_data.py
python tools/simulate_balance.py
python tools/build_prototype.py
```

### Проверка целостности

```powershell
cd financial-tamagotchi
python tools/validate_data.py
node tools/test_prototype.js
```

## Ограничения

- Все данные синтетические: они сгенерированы по правилам, а не собраны с людей.
- 6 игровых пользователей и 30 дней — иллюстрация, а не статистическая значимость.
- Симуляция баланса — математическая модель, а не A/B-тест на реальных игроках.
- `MOCK_DATA` не про финансы: в нём нет сумм, категорий и дат.
- Корреляции в модели отражают заложенные формулы. На реальных людях выводы нужно проверять отдельно.

## Что можно улучшить

1. Добавить единый `user_id`, даты и события продукта во все таблицы.
2. Собрать реальные или правдоподобные транзакции вместо одного флага «пользуется приложением».
3. Увеличить игровую выборку и добавить когорты.
4. Пересмотреть квесты с нулевым выполнением и проверить сложность через A/B-тест.
5. Добавить в анализ retention, конверсию в покупку косметики и время до первой траты.
